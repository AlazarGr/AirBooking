# Сервис бронирования авиабилетов (Airline Booking System)

## 1. Наведение и общая концепция проекта
**Airline Booking System** — монолитное бэкенд-приложение, предназначенное для автоматизации процессов управления расписанием рейсов, поиска билетов и бронирования мест пассажирами. Проект разработан в рамках лабораторного практикума для реализации надежного серверного ядра и строгого соблюдения бизнес-инвариантов предметной области[cite: 11].

Система решает следующие ключевые задачи:
* Ведение справочника аэропортов[cite: 3].
* Управление жизненным циклом рейсов (создание, отмена, расчет доступных мест)[cite: 3, 6, 7].
* Создание, подтверждение и отмена бронирований для групп пассажиров (от 1 до 5 человек в одном заказе)[cite: 5, 6, 7].
* Обеспечение ролевой модели доступа (Администратор и Пассажир).

---

## 2. Архитектурный и технологический стек
Приложение построено с использованием современной экосистемы Java/Kotlin и следует принципам многоуровневой архитектуры:
* **Язык программирования:** Java[cite: 2]
* **Фреймворк:** Spring Boot[cite: 2] (Spring Data JPA / Hibernate[cite: 2], Spring Security для авторизации)
* **Система сборки:** Maven[cite: 2]
* **Реляционная база данных:** PostgreSQL[cite: 2]
* **Миграции базы данных:** Liquibase[cite: 2]
* **Интерфейс взаимодействия:** REST API (JSON, Bean Validation)[cite: 2] + Веб-интерфейс / Swagger UI.

### Архитектурные принципы
1. **Строгое разделение ответственности:** приложение разделено на слои `Controller` (обработка HTTP-запросов), `Service` (реализация бизнес-логики и инвариантов) и `Repository` (взаимодействие с базой данных)[cite: 9].
2. **DTO vs Persistence:** DTO-модели для HTTP-запросов и ответов полностью отделены от JPA Entity (persistence-моделей)[cite: 9]. Прямое использование сущностей базы данных в контроллерах запрещено.
3. **Централизованная обработка ошибок:** все бизнес-ошибки (например, нехватка мест, нарушение статусной модели) перехватываются глобальным обработчиком исключений и возвращаются в стандартизированном JSON-формате с кастомными кодами (например, `NOT_ENOUGH_SEATS`), исключая падения со стандартным кодом `500 Internal Server Error`[cite: 9, 10].

## 3. Ролевая модель и авторизация
В системе реализовано разграничение прав доступа на базе ролей (Role-Based Access Control):
* **`ROLE_USER` (Пассажир / Клиент):**
  * Поиск рейсов.
  * Создание, просмотр, подтверждение и отмена собственных бронирований.
* **`ROLE_ADMIN` (Администратор авиакомпании):**
  * Создание новых рейсов в расписании.
  * Отмена существующих рейсов (`SCHEDULED` -> `CANCELLED`)[cite: 6].
  * Полный доступ к управлению справочными данными.

## 4. Доменная модель и структура базы данных
Управление структурой базы данных выполняется декларативно через скрипты миграций **Liquibase**[cite: 2, 8]. Схема включает следующие основные таблицы[cite: 8]:

1. **`airport` (Аэропорты):**
   * `id` (Primary Key)[cite: 3]
   * `iata_code` (Уникальный IATA-код, например, `SVO`, `OMS`, `LED`)[cite: 3]
   * `name` (Название аэропорта)[cite: 3]
   * `city` (Город)[cite: 3]
   * *Примечание:* Заполняется справочными данными при миграции[cite: 3].

2. **`flight` (Рейсы):**
   * `id` (Primary Key)[cite: 3]
   * `flight_number` (Номер рейса)[cite: 3]
   * `departure_airport_id` (Ссылка на аэропорт отправления)[cite: 3]
   * `arrival_airport_id` (Ссылка на аэропорт назначения)[cite: 3]
   * `departure_time` (Дата и время отправления)[cite: 4]
   * `arrival_time` (Дата и время прибытия)[cite: 4]
   * `economy_seats` (Общее количество мест эконом-класса)[cite: 4]
   * `business_seats` (Общее количество мест бизнес-класса)[cite: 5]
   * `status` (`SCHEDULED` / `CANCELLED`)[cite: 3, 4]

3. **`booking` (Бронирования):**
   * `id` (Primary Key)[cite: 4]
   * `booking_code` (Уникальный буквенно-цифровой код бронирования, например, `F8K2LM`)[cite: 4, 5, 7]
   * `flight_id` (Ссылка на рейс)[cite: 4]
   * `service_class` (`ECONOMY` / `BUSINESS`)[cite: 4, 7]
   * `status` (`CREATED` / `CONFIRMED` / `CANCELLED`)[cite: 4, 5]
   * `created_at`, `confirmed_at`, `cancelled_at` (Временные метки)[cite: 4]

4. **`booking_passenger` (Пассажиры бронирования):**
   * `id` (Primary Key)
   * `booking_id` (Ссылка на бронирование)[cite: 8]
   * `full_name` (ФИО пассажира)[cite: 5]
   * `birth_date` (Дата рождения)[cite: 5]
   * `document_number` (Номер документа/паспорта)[cite: 5]

## 5. Основной функционал и Бизнес-правила

### Бизнес-правила для рейсов:
1. Аэропорт отправления и аэропорт назначения не могут совпадать[cite: 6].
2. Время отправления должно быть строго меньше времени прибытия[cite: 6].
3. Запрещено создание рейса с датой отправления в прошлом[cite: 6].
4. Количество мест каждого класса обслуживания не может быть отрицательным[cite: 6].
5. Комбинация номера рейса и даты/времени отправления должна быть уникальной[cite: 6].
6. Создание бронирований разрешено только на рейсы со статусом `SCHEDULED`[cite: 6].

### Бизнес-правила для бронирований:
1. Одно бронирование должно содержать от 1 до 5 пассажиров[cite: 6, 7].
2. Все пассажиры в рамках одного бронирования занимают места единого класса обслуживания (`ECONOMY` или `BUSINESS`)[cite: 7].
3. Невозможно забронировать больше мест, чем реально доступно на рейсе в выбранном классе[cite: 7].
4. Бронирования в статусах `CREATED` и `CONFIRMED` блокируют места (участвуют в расчете доступных мест). Отмененные бронирования (`CANCELLED`) места не занимают[cite: 7].
5. Запрещено создание бронирования после фактического отправления рейса[cite: 7].
6. Изменение статусов бронирований и рейсов выполняется исключительно через специальные бизнес-операции (подтверждение, отмена), прямое изменение через універсальный `PATCH` заблокировано[cite: 8].
7. Номер документа пассажира не должен дублироваться внутри одного бронирования[cite: 8].
8. Один и тот же пассажир не может иметь несколько активных бронирований на один и тот же рейс[cite: 8].

## 6. Спецификация REST API

| Метод | Эндпоинт | Описание | Доступная роль |
| :--- | :--- | :--- | :--- |
| `POST` | `/flights` | Создание нового рейса[cite: 4] | `ROLE_ADMIN` |
| `GET` | `/flights/{id}` | Получение информации о рейсе по ID[cite: 4] | Все пользователи |
| `GET` | `/flights?from=...&to=...&date=...` | Поиск рейсов с расчетом свободных мест[cite: 4, 5] | Все пользователи |
| `POST` | `/flights/{id}/cancel` | Отмена рейса[cite: 6] | `ROLE_ADMIN` |
| `POST` | `/bookings` | Создание нового бронирования в статусе `CREATED`[cite: 5] | `ROLE_USER`, `ROLE_ADMIN` |
| `GET` | `/bookings/{id}` | Получение информации о бронировании по ID[cite: 5] | `ROLE_USER`, `ROLE_ADMIN` |
| `GET` | `/bookings/by-code/{code}` | Поиск бронирования по уникальному коду (например, `F8K2LM`)[cite: 5] | `ROLE_USER`, `ROLE_ADMIN` |
| `POST` | `/bookings/{id}/confirm` | Подтверждение бронирования (`CREATED` -> `CONFIRMED`)[cite: 5, 6] | `ROLE_USER`, `ROLE_ADMIN` |
| `POST` | `/bookings/{id}/cancel` | Отмена бронирования и освобождение мест[cite: 6] | `ROLE_USER`, `ROLE_ADMIN` |
