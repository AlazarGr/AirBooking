# Сервис бронирования авиабилетов (Airline Booking System)

## 1. Наведение и общая концепция проекта
**Airline Booking System** — монолитное бэкенд-приложение, предназначенное для автоматизации процессов управления расписанием рейсов, поиска билетов и бронирования мест пассажирами. Проект разработан в рамках лабораторного практикума для реализации надежного серверного ядра и строгого соблюдения бизнес-инвариантов предметной области[cite: 11].

Система решает следующие ключевые задачи:
* Ведение справочника аэропортов.
* Управление жизненным циклом рейсов (создание, отмена, расчет доступных мест).
* Создание, подтверждение и отмена бронирований для групп пассажиров (от 1 до 5 человек в одном заказе).
* Обеспечение ролевой модели доступа (Администратор и Пассажир).

---

## 2. Архитектурный и технологический стек
Приложение построено с использованием современной экосистемы Java и следует принципам многоуровневой архитектуры:
* **Язык программирования:** Java
* **Фреймворк:** Spring Boot (Spring Data JPA / Hibernate[cite: 2], Spring Security для авторизации)
* **Система сборки:** Maven
* **Реляционная база данных:** PostgreSQL
* **Миграции базы данных:** Liquibase
* **Интерфейс взаимодействия:** REST API (JSON, Bean Validation) + Веб-интерфейс / Swagger UI.

### Архитектурные принципы
1. **Строгое разделение ответственности:** приложение разделено на слои `Controller` (обработка HTTP-запросов), `Service` (реализация бизнес-логики и инвариантов) и `Repository` (взаимодействие с базой данных).
2. **DTO vs Persistence:** DTO-модели для HTTP-запросов и ответов полностью отделены от JPA Entity (persistence-моделей). Прямое использование сущностей базы данных в контроллерах запрещено.
3. **Централизованная обработка ошибок:** все бизнес-ошибки (например, нехватка мест, нарушение статусной модели) перехватываются глобальным обработчиком исключений и возвращаются в стандартизированном JSON-формате с кастомными кодами (например, `NOT_ENOUGH_SEATS`), исключая падения со стандартным кодом `500 Internal Server Error`.

## 3. Ролевая модель и авторизация
В системе реализовано разграничение прав доступа на базе ролей (Role-Based Access Control):
* **`ROLE_USER` (Пассажир / Клиент):**
  * Поиск рейсов.
  * Создание, просмотр, подтверждение и отмена собственных бронирований.
* **`ROLE_ADMIN` (Администратор авиакомпании):**
  * Создание новых рейсов в расписании.
  * Отмена существующих рейсов (`SCHEDULED` -> `CANCELLED`).
  * Полный доступ к управлению справочными данными.

## 4. Доменная модель и структура базы данных
Управление структурой базы данных выполняется декларативно через скрипты миграций **Liquibase**. Схема включает следующие основные таблицы:

1. **`airport` (Аэропорты):**
   * `id` (Primary Key)
   * `iata_code` (Уникальный IATA-код, например, `SVO`, `OMS`, `LED`)
   * `name` (Название аэропорта)
   * `city` (Город)
   * *Примечание:* Заполняется справочными данными при миграции.

2. **`flight` (Рейсы):**
   * `id` (Primary Key)
   * `flight_number` (Номер рейса)
   * `departure_airport_id` (Ссылка на аэропорт отправления)
   * `arrival_airport_id` (Ссылка на аэропорт назначения)
   * `departure_time` (Дата и время отправления)
   * `arrival_time` (Дата и время прибытия)
   * `economy_seats` (Общее количество мест эконом-класса)
   * `business_seats` (Общее количество мест бизнес-класса)
   * `status` (`SCHEDULED` / `CANCELLED`)

3. **`booking` (Бронирования):**
   * `id` (Primary Key)
   * `booking_code` (Уникальный буквенно-цифровой код бронирования, например, `F8K2LM`)
   * `flight_id` (Ссылка на рейс)
   * `service_class` (`ECONOMY` / `BUSINESS`)
   * `status` (`CREATED` / `CONFIRMED` / `CANCELLED`)
   * `created_at`, `confirmed_at`, `cancelled_at` (Временные метки)

4. **`booking_passenger` (Пассажиры бронирования):**
   * `id` (Primary Key)
   * `booking_id` (Ссылка на бронирование)
   * `full_name` (ФИО пассажира)
   * `birth_date` (Дата рождения)
   * `document_number` (Номер документа/паспорта)

## 5. Основной функционал и Бизнес-правила

### Бизнес-правила для рейсов:
1. Аэропорт отправления и аэропорт назначения не могут совпадать.
2. Время отправления должно быть строго меньше времени прибытия.
3. Запрещено создание рейса с датой отправления в прошлом.
4. Количество мест каждого класса обслуживания не может быть отрицательным.
5. Комбинация номера рейса и даты/времени отправления должна быть уникальной.
6. Создание бронирований разрешено только на рейсы со статусом `SCHEDULED`.

### Бизнес-правила для бронирований:
1. Одно бронирование должно содержать от 1 до 5 пассажиров.
2. Все пассажиры в рамках одного бронирования занимают места единого класса обслуживания (`ECONOMY` или `BUSINESS`).
3. Невозможно забронировать больше мест, чем реально доступно на рейсе в выбранном классе.
4. Бронирования в статусах `CREATED` и `CONFIRMED` блокируют места (участвуют в расчете доступных мест). Отмененные бронирования (`CANCELLED`) места не занимают.
5. Запрещено создание бронирования после фактического отправления рейса.
6. Изменение статусов бронирований и рейсов выполняется исключительно через специальные бизнес-операции (подтверждение, отмена), прямое изменение через універсальный `PATCH` заблокировано.
7. Номер документа пассажира не должен дублироваться внутри одного бронирования.
8. Один и тот же пассажир не может иметь несколько активных бронирований на один и тот же рейс.

## 6. Спецификация REST API

| Метод | Эндпоинт | Описание | Доступная роль |
| :--- | :--- | :--- | :--- |
| `POST` | `/flights` | Создание нового рейса | `ROLE_ADMIN` |
| `GET` | `/flights/{id}` | Получение информации о рейсе по ID | Все пользователи |
| `GET` | `/flights?from=...&to=...&date=...` | Поиск рейсов с расчетом свободных мест | Все пользователи |
| `POST` | `/flights/{id}/cancel` | Отмена рейса | `ROLE_ADMIN` |
| `POST` | `/bookings` | Создание нового бронирования в статусе `CREATED` | `ROLE_USER`, `ROLE_ADMIN` |
| `GET` | `/bookings/{id}` | Получение информации о бронировании по ID | `ROLE_USER`, `ROLE_ADMIN` |
| `GET` | `/bookings/by-code/{code}` | Поиск бронирования по уникальному коду (например, `F8K2LM`) | `ROLE_USER`, `ROLE_ADMIN` |
| `POST` | `/bookings/{id}/confirm` | Подтверждение бронирования (`CREATED` -> `CONFIRMED`) | `ROLE_USER`, `ROLE_ADMIN` |
| `POST` | `/bookings/{id}/cancel` | Отмена бронирования и освобождение мест | `ROLE_USER`, `ROLE_ADMIN` |
